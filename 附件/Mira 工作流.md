# Mira 田野记录会审

在 Mira 桌面版开一个独立对话，载入含 trenches.json 的附件。每轮保留上轮的证据记录编号。如果工具无法执行，请明确标记运行位置，附上在同一目录终端得到的真实输出。

## 田野笔记

> 读取 trenches.json。用你自己的话写出箭头方向、单元与记录编号的对应关系。先在南北双沟中找一条由两次观察组成的可证先后路径，再找一对没有直接或间接联系的单元。保留原单元代号与剖面编号。

## 时间线候选

> 执行 python analyze.py trenches.json。逐探方报告直接观察数、可证关系数和合法排列数。只在所有合法排列都支持的情况下写“先于”。出现 review-records 时，停止该探方的年代排序，将回路和记录编号移交复核。

## 交叉检验

> 用 python verify.py 对照穷举结果。解释为什么台地拼方五个单元仍有 30 种排列。两种算法若不一致，给出第一个不一致探方并保留原始输入。

## 复核单

> 运行 python stress.py，读取 stress.json。按证据编号总结逐条暂时搁置的后果。不要改动原始记录，列出田野人员要回查的三份证据和各自理由。让读者在文末能找到每个数字的文件来源，然后保留本次真实对话供分享。

## 补充轮 · 复核实验 v2

> 读取 survey_plans.json，分别圈定已知顺序和可接近的单元对。运行 survey.py，在两个方法首轮相同的现场条件下检查第二轮怎样依第一轮的方向而变。任选一条 all_hidden_orders.csv 的模拟真序验证它始终被保留。若观察无结果，保留原候选并标记未判。

本轮使用 `复核实验/` 子目录。将新输入、复核输出、反例与 v1 演示分别署明来源。没有可用执行器时记录执行地点与真实终端输出。
